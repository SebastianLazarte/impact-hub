# 0006. Define each page's data once, in an Alba resource, and generate its TypeScript type with Typelizer

Status: Accepted (2026-11-21)
Answers: Q3

## Context
Q3 asks for three things:
- pages show numbers as text formatted on the server, and compute none;
- the data a page receives has one definition;
- a mismatch between the server and the page fails the build.

Today the home page's prop types are written by hand in its `.tsx` file, so a change
on the server would not fail the build. The team in research R9 uses Alba serializers
with TypeScript types generated by Typelizer. Sebastian Lazarte approved the two gems
`alba` and `typelizer` on 2026-11-21.

## Decision
- **Gems:** `alba` and `typelizer`, both in the default group (the DSL is referenced
  when resources load; Typelizer switches it off outside development). No `listen`.
- **One resource per page.** Each Inertia page gets its props from exactly one resource
  in `app/resources/`. `ApplicationResource` does `include Alba::Resource` and
  `helper Typelizer::DSL`. A controller passes `SomePageResource.new(obj).serializable_hash`
  and nothing else.
- **Every attribute is typed.** Any attribute that is not an ActiveRecord column is
  typed with `typelize`: string-literal unions for statuses, `nullable` wherever a value
  can be unknown. Resources over plain Ruby objects get no inference, so an untyped
  attribute becomes `unknown`, and `tsc` rejects it wherever a page uses it.
- **Generated types are committed** under `app/frontend/types/serializers/`
  (Typelizer's default under Vite's source folder). Pages import their prop types from
  there; there are no hand-written prop types.
- **Numbers cross as formatted strings** ("11,359 J", "600 mm"). Pages do no arithmetic
  and format no numbers.
- **CI** runs `TYPELIZER=true bin/rails typelizer:types:refresh`, then fails if
  anything under `app/frontend/types/serializers/` changed or appeared. Then
  `npm run check` fails on any page that uses a prop wrongly. `TYPELIZER=true` is
  needed because Typelizer turns its DSL off outside development.
- **Development:** `bin/rails typelizer:types` after changing a resource; Typelizer's
  development middleware also regenerates while `bin/dev` runs.

**Options considered:**
- Our own generator, about 150 lines with no new gems: it rebuilds Typelizer and
  doesn't use the team's tools.
- Hand-written types plus a JSON Schema check: two new packages, and still two
  definitions.

## Consequences
- A page's data has one definition, and drift between the server and the page fails CI.
- Reviews include the generated files.
- A Typelizer upgrade can change its output; refresh the types and review the diff.
- The first resource built over a plain Ruby object is checked by hand before any page
  is built on it (design.md, Risks).
